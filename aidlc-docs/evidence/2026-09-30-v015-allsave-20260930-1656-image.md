## 3. 包内静态核验（双层解包）

### 3.1 板型与分区

- `rkImageMaker -unpack`（v2.2，退出码 0）→ `boot.bin`(268,736) + `firmware.img`；
  `afptool -unpack`（v2.2，退出码 0）→ `Image/{env,idblock,uboot,boot,oem,userdata,rootfs}.img` + `package-file` + `download.bin`。
- `package-file` 分区清单：`env / idblock / uboot / boot / oem / userdata / rootfs`（+ `package-file`、`bootloader`）——
  与 `build_info.txt` 的 `RK_PARTITION_ARGS` 一致。
- `env.img` 内命令行实证：`blkdevparts=mmcblk0:32K(env),512K@32K(idblock),256K(uboot),32M(boot),512M(oem),256M(userdata),6G(rootfs)`。
- `update.img` 头：`RKFW` magic，芯片串 `6011`（与既有 V015 候选**同板型**，仅时间戳字节不同）；`download.bin` 头 `LDR `（RKBOOT），内部符号全为 `rv1106_*`。
- 解包出的 `rootfs/boot/oem/userdata.img` 与 `IMAGES/` 同名文件**逐字节一致**；`rkImageMaker` 导出的 `boot.bin` 与 `download.bin` 哈希一致。

### 3.2 `boot.img`（FIT）内确为 V015 DTB

- `boot.img` 是 **FIT**（`FIT image with Linux kernel, FDT blob and resource`），不是 Android boot。
- `dtc -I dtb -O dts` 读出 `fdt` 节点：`data-position=0x800 / data-size=0x12f52`，
  头内自证 `hash value = d540ab24319e7fe210e888a5ec7f888564941bc319fa2bf8aed5c5b60a2806e5`。
- 切出该段（`dd`）后哈希 = `d540ab24319e7fe210e888a5ec7f888564941bc319fa2bf8aed5c5b60a2806e5`，
  **= 构建产出的 `sysdrv/out/bin/board_uclibc_rv1106/rv1106g-dw-tly-v015.dtb`**（两处构建副本同哈希）。
- 反编译该 DTB：`model = "Dongwei DW-TLY-V015 eMMC"`、`compatible = "dongwei,dw-tly-v015"...`；
  `mmc@ffaa0000`（&sdmmc）`bus-width = <0x04>`、`max-frequency = <0x2faf080>`(50MHz)、`non-removable`、`supports-sdio`、`status = "okay"`；
  `syscon@ff538000` `compatible = "rockchip,rv1106-ioc"`（**grf.c 的匹配键确实存在于镜像内 DTB**）；`ramoops@d00000` 存在。
- **该 DTB 与旧候选 20260930.1022 内的 DTB 同哈希**（`d540ab24…`）——本次源码改动是纯注释，不改 DTB。

### 3.3 内核：`CONFIG_ROCKCHIP_GRF=y` 与 GRF 符号（修复确实在镜像里）

- `sysdrv/source/objs_kernel/.config:4232 CONFIG_ROCKCHIP_GRF=y`。
- `grf.o` 存在；`strings grf.o` 含 `rockchip,rv1106-ioc` 与 `jtag sdmmc force`。
- `System.map` 含 `rockchip_grf_init`、`rv1106_ioc_grf`、`rv1106_ioc_defaults` 与
  `__initcall__kmod_grf__164_409_rockchip_grf_init2`（对应源码 `postcore_initcall`，早于 mmc probe）。
- **镜像内内核**：FIT `kernel` 节点 `data-position=0x13800 / data-size=0x382488`，切出后哈希
  `0f455422d16f3fda222bc257ec3cdbdca5bb2abf131770e75af1fde5ef741057`，**= 构建 `arch/arm/boot/zImage`**。
  未压缩 `arch/arm/boot/Image` 内可 `strings` 到 `rockchip,rv1106-ioc` 与 `jtag sdmmc force`。
- **与修复前候选的内核不同**：20260930.1022 的 FIT kernel 为 `data-size=0x3823a8`、哈希
  `8ddb8b7da1cffd0d1181ecc9a2b994a9d0d6cf1724eedebf695604f4e5eff9c1` ⇒ 本候选内核**确已含 `grf.o`**
  （新内核大 1,248 B），即新镜像**真正带上了 `force_jtag_sdmmc` 修复**，不是空转重打包。

### 3.4 rootfs：无 `S91smb`，Samba 二进制保留
